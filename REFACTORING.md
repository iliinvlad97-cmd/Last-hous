# Безопасный рефакторинг существующей игры

Исходная точка: `42854919b6e9dba7b55981ec9f4db86b9e9e0ec4`.
И локальный checkout, и удалённая `main` на момент работы содержат v0.9.5.4,
а не указанную в задании v0.9.5.5. Поведение этой исходной версии сохранено;
новые механики v0.9.6 не добавлялись.

## Разделение ответственности

Все классы остаются в `com.lastdom.game`; перемещение между Java-пакетами
и расширение публичного API для этого этапа не требуются.

| Файл | Ответственность |
| --- | --- |
| `MainActivity.java` | Создание View, полноэкранный режим, сохранение при `onPause` |
| `GameView.java` | Canvas View, графические примитивы, обработка касаний, исходный Handler-цикл |
| `GameState.java` | Состояние с прежними начальными значениями, включая временные UI-селекции и визуальные кеши |
| `GameController.java` | Время, ресурсы, назначения/AI, события, ремонт, улучшения, существующие экспедиции |
| `GameSaveStore.java` | Чтение/запись существующих SharedPreferences |
| `Resident.java`, `Location.java` | Прежние модели Survivor и Location |
| `ShelterGeometry.java` | Координаты сцены, hitbox комнат, слоты жителей и сохранённая legacy-геометрия |
| `ShelterRenderer.java` | Главная сцена, состояние убежища, освещение, эффекты и legacy-отрисовка |
| `ResidentRenderer.java` | Персонажи, портреты, анимация и визуальные состояния |
| `HudRenderer.java` | Заголовок, ресурсы, нижнее меню |
| `OverlayRenderer.java` | Панели жителей/комнат, события, меню работы, журнал, существующая карта |

Контроллер наследует данные `GameState`, а View и renderer-классы используют
один экземпляр контроллера. Это сохраняет порядок чтения и изменения общего
состояния. Renderer-классы используют прежний общий `Paint`: его состояние
и порядок команд рисования также не менялись. Неиспользуемые legacy-методы
сохранены, а не удалены как часть рефакторинга.

## Совместимость

- Имя хранилища `save_v02`, все ключи, значения по умолчанию, разделитель
  журнала и вызовы `apply()` сохранены. Миграция не нужна.
- PNG, AndroidManifest, ресурсы, room hitbox, позиции персонажей и меню
  не изменены. Тела всех 88 прежних методов совпадают после нормализации
  ссылок на новые компоненты, переименования модели и форматирования строк.
- Сохранены tick через 1000 мс, скорости x1/x2/x4, pause и блокировка времени
  событием/поражением. Не изменены формулы производства, расхода и случайностей.
- Сохранён touch-routing: модальные состояния и overlay поглощают касание;
  персонаж проверяется раньше комнаты; выход в город и меню остаются на
  прежних координатах. Как в исходнике, выход в город проверяется до персонажей.
- Lifecycle не исправлялся попутно: `onPause` сохраняет состояние, но сам
  по себе не останавливает Handler.

## Проверки

Использовать существующую установленную среду (wrapper в проекте отсутствует):

```bash
source /workspace/tooling/last-hous-env.sh
cd /workspace/Last-hous
python3 tools/refactor_regression.py
gradle --no-daemon --max-workers=2 \
  --project-cache-dir /workspace/tooling/project-cache \
  assembleDebug lintDebug testDebugUnitTest
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify \
  app/build/outputs/apk/debug/app-debug.apk
```

`tools/refactor_regression.py` требует Python 3, полный JDK 21 и исходный
коммит в локальной Git-истории. Сторонних библиотек и изменений Gradle не
требуется. Он компилирует исходную и новую версии во временном каталоге,
запускает одинаковые сценарии с фиксированным временем анимации/случайностями,
сравнивает состояния, сохранения и команды Canvas. Android-классы заменены
тестовыми двойниками только во временных копиях.

Результат: 122 сравнения с исходной версией и 175 проверок в каждой версии.
Покрыты старые сохранения с отсутствующими ключами, roundtrip с активными
таймерами, время/пауза/скорости, ресурсы, назначения, все пять событий и оба
выбора, ремонт/строительство, шесть существующих точек экспедиций, сетка
hitbox при трёх высотах экрана, слоты персонажей, касания, overlay и отрисовка.

`assembleDebug` и проверка подписи APK прошли. `lintDebug`: 0 ошибок,
24 предупреждения, как до рефакторинга. `testDebugUnitTest`: `NO-SOURCE`,
а не выполненные JUnit-тесты. Проверки на Android-устройстве/эмуляторе
и сравнение реальных пикселей не выполнялись.
